# Room-image placement math

`Storyboard.Foundation.Spatial.RoomImagePlacementMath` relocates the current hosted directional room-image placement calculation into a UI-independent resolver. Designer can use its six numeric coordinates for preview/export and its four transformed corners for corner snapping. Runtime consumers receive explicit placement and do not infer it from the slot.

## Inputs and coordinates

Coordinates use room-image pixels with a top-left origin, positive X rightward, positive Y downward, and clockwise positive rotation. The caller supplies the effective room width/height, full native bitmap width/height, authored pixel offsets, slot, and rotation. Bitmap bounds include transparent pixels. There is no implicit image or room scale.

The method requires finite positive room and bitmap dimensions, finite authored offsets, finite rotation, and a recognized slot. It throws `ArgumentOutOfRangeException` for invalid values. Pixel dimensions must be resolved by the caller from the same staged image bytes that preview/export will use. The resolver does no file I/O and does not treat an unreadable/missing bitmap dimension as equal to the room dimension; callers must report that inability to resolve placement.

## Resolution

For logical slot anchor `A`, authored adjustment `U`, selected bitmap anchor fraction `f`, bitmap dimensions `(W,H)`, and screen-space rotation `R`:

```text
q = (f.x × W, f.y × H)
IconOffset = U - R(q)
DrawOrigin = A + IconOffset
CornerInRoom = DrawOrigin + R(native bitmap corner)
```

The slot point and inward direction match the current hosted map. Down anchors at the room origin; Default and Up anchor at the room center. Other slots anchor at their existing edge or corner positions. The bitmap anchor is resolved by inverse-rotating the slot's inward vector, retaining the hosted `0.0001` component threshold; near-zero rotated coordinate residue below `1e-10` is normalized to zero. Every finite legacy rotation is accepted, including negative and non-quarter-turn values.

The result exposes `AnchorX/Y`, `IconOffsetX/Y`, `X/Y`, and the transformed top-left, top-right, bottom-right, and bottom-left corners. `X = AnchorX + IconOffsetX` and `Y = AnchorY + IconOffsetY`; fractional coordinates are kept. The corners use the entire native bitmap rectangle, without alpha inspection or room clipping.

## Fixed examples

For a 1600 × 800 room and 400 × 200 bitmap:

| Slot | Rotation | Authored offset | Anchor | Icon offset | Draw origin |
| --- | ---: | --- | --- | --- | --- |
| Down | 0° | `(0,0)` | `(0,0)` | `(0,0)` | `(0,0)` |
| Down | 90° | `(0,0)` | `(0,0)` | `(200,0)` | `(200,0)` |
| North | 0° | `(30,15)` | `(800,0)` | `(-170,15)` | `(630,15)` |
| North | 90° | `(30,15)` | `(800,0)` | `(130,15)` | `(930,15)` |
| East | 0° | `(0,0)` | `(1600,400)` | `(-400,-100)` | `(1200,300)` |
| South | 0° | `(0,0)` | `(800,800)` | `(-200,-200)` | `(600,600)` |
| West | 0° | `(0,0)` | `(0,400)` | `(0,-100)` | `(0,300)` |
| Up | 0° | `(0,0)` | `(800,400)` | `(-200,-100)` | `(600,300)` |

These values are fixed-coordinate expectations, not outputs generated by another placement helper.

## Scope

The resolver does not inspect alpha bounds, load assets, apply object placement behavior, clip rendering, mutate attachment state, or implement lighting. Existing `RenderablePlacementMath` continues to own object transforms and is unchanged.
